# 문제 등록(intake) 테스트 기록

각 항목은 **무엇을 했는지 → 실행한 명령 → 나온 출력 → 결론** 순서입니다. "이 대화에서 확인"으로 표시한 출력은 터미널 결과를 그대로 옮겼습니다. "이전 대화"로 표시한 항목은 요약에 남은 내용이라 세부 출력은 없습니다.

## A. 이전 대화에서 한 테스트 (요약 기준)

| 테스트 | 한 일 | 결과 | 결론 |
|---|---|---|---|
| 1단계 코드 테스트 | `python run_all_tests.py` | 실패가 `.env`의 API 키 때문에 나던 것을 분리해 통과시킴 | AI 없이 돌아가는 검사는 정상 |
| 2단계 프롬프트 시험 | `run_ai_tests.py`로 T1~T33을 실제 AI에 보냄 | 강한 모델에서 T1~T20, T27~T33 통과 확인. T21~T26은 약한 lite 모델에서만 확인 | 33개를 한 번에 전부 통과시킨 실행은 없음 |

## B. 이 대화에서 한 테스트

### B-1. 엑셀 배치 1 재실행 (7문제, gemini-3.5-flash)
- 명령: `python run_real_e2e.py --xlsx sample1b.xlsx --model gemini-3.5-flash`
- 출력(발췌):
```
작업 상태: done | 처리 7/7 | 상태별 {'held': 2, 'needs_review': 5}
[needs_review] C07_02       디버깅  테스트 1 조건 1 코드 ['c']
[needs_review] JAVA08_01    코딩   테스트 1 조건 1 코드 ['java']
     · 승인 이유: 엑셀 값과 달라진 항목이 있습니다: 기대 출력. 의도한 정정인지 확인하세요.
[held        ] PY08_01      ... 보류사유: 엑셀 이름 'PY08_01 객체지향 프로그래밍1'이 중복되어 나타남 (행 6, 7)
[needs_review] PY10_02-확인학습 디버깅  테스트 1 조건 2 코드 ['python']
승인 결과: {'registered': 5}
```
- 결론:
  - 이름이 같은 두 행은 잘못 등록하지 않고 보류했습니다. 의도대로입니다.
  - AI가 제목을 줄였습니다("C07_02 이중포인터" → "C07_02", "PY10_02 확인학습" → "PY10_02-확인학습"). → 서버가 엑셀 이름으로 되돌리도록 고쳤습니다.
  - JAVA08_01은 AI가 기대 출력을 바꿨고, 엑셀 값 변경 감지가 잡았습니다.

      기대출력 엑셀: '첫 번째 정수 입력: 10\n두 번째 정수 입력: 2\n나눗셈 결과: 5\n...'

### B-4. 워드 파일 (week08 풀이, 5문제)
- 명령: `python run_real_e2e.py --hwp cpp_week08_복사와이동생성자_풀이.docx --model gemini-3.5-flash`
- 첫 출력: `상태별 {'blocked': 1, 'needs_review': 4}`
  - `[blocked] C++_08_01 ... 검사 실패: schema: 문제 전체 - Value error, 테스트 케이스가 없으면 problem_condition(AI 채점 조건)이 최소 1개 필요합니다.`
- 원인: 이 문제는 main과 입출력 예가 없는데 AI가 조건도 만들지 않았습니다.
- 고친 것: 프롬프트에 "테스트 케이스를 만들 수 없으면 `[필수]` 조건을 1개 이상 쓴다" 규칙을 추가했습니다.
- 재실행 출력: `상태별 {'needs_review': 5}` (C++_08_01 조건 2개)
- 결론: 워드 단독 업로드는 5/5 처리됐습니다. 그림 속 실행 결과는 읽을 수 없어서 AI가 손 추적으로 채운 곳에 `확인필요`가 달렸습니다.

### B-5. 실제 서버(uvicorn)로 올린 작업
- 명령: `python dev_server.py --port 8765 ...` 후 `curl -X POST /intake/jobs -F files=@...`, `GET /intake/jobs/{id}`, `POST .../resume`, `POST .../approve`
- 워드 작업:
```
{"job_id":"3d80f0ac-...","status":"processing","input_kind":"원본","records_total":5,...}
processing {'pending': 4, 'processing': 1}  (8분 넘게 반복)
paused {'ai_failed': 3, 'pending': 2}
{"job_id":"3d80f0ac-...","status":"processing","retry_items":3}      ← resume
done {'needs_review': 5}
{"summary":{"registered":5},"results":[...]}                        ← approve
```
- 결론: 업로드는 즉시 202로 돌아오고 백그라운드로 처리됩니다. 첫 모델(gemini-3.5-flash)의 한도로 3건이 실패해 paused가 됐고, 서버를 다른 모델(gemini-3.6-flash)로 다시 띄운 뒤 `resume`으로 실패한 3건만 이어서 처리했습니다. 작업 상태가 DB에 남아서 서버를 껐다 켜도 이어졌습니다.
- PDF 작업: `done {'needs_review': 5}` — 5개 모두 검사 실패 없음.
- 한글(.hwp) 작업: `done {'held': 2, 'needs_review': 5}`
  - 보류 2건: C++_06_01 "문제 설명에 외부 교재의 문제('4장 개념 확인 11번')만 언급…", C++_06_02 "원본조각에 문제 본문 내용…이 없고 양식 문구만 존재…"
  - 결론: 본문이 없는 문제는 AI가 지어내지 않고 보류했습니다.
- 같은 문서를 형식만 바꿔 올리면 유형이 다르게 나왔습니다(C++_08_02: 워드는 디버깅, PDF는 코딩). 기준 확인이 필요합니다.

### B-6. 객관식·단답형·주관식 8문제 (실제 서버)
- 명령: `python make_obj.py` 후 `curl -X POST /intake/jobs -F files=@sample_obj.xlsx`
- 처리된 항목의 결과:

| 문제 | 상태 | 결과 |
|---|---|---|
| OBJ_01 | registered | `correct_answers [1]` (정답 "2"를 인덱스로) |
| OBJ_02 | registered | `correct_answers [0, 2]` ("①, ③") |
| OBJ_03 | registered | 정답 칸이 비어 AI가 `[2]`를 채움 → `ai_filled ['correct_answers']`. 정답은 맞았음 |
| SA_01 | registered | `answer_text ["40"]` |
| SA_02 | registered | `answer_text {"1": ["virtual"], "2": ["추상"]}` |

- 이어서 정지: 사용자가 붙여 준 출력.
```
1 registered OBJ_01 포인터 기초 None
...
5 registered SA_02 빈칸 채우기 None
6 processing None None
7 pending None None
8 pending None None
```
  - 6번(SA_03)이 30분 넘게 `processing`이었습니다. 서버 로그에는 오류가 없었습니다.
- 원인: AI 호출에 전체 제한 시간이 없었습니다(`asyncio.to_thread`가 끝나기만 기다림).
- 고친 것: 문제 하나당 `INTAKE_AI_ITEM_TIMEOUT`(기본 420초)를 넣어, 넘으면 `ai_failed`로 처리하고 다음 문제로 넘어가게 했습니다.
- 재시작 후 `resume`은 한 번 "아직 처리 중입니다"(409)를 돌려줬습니다. 이전 프로세스의 heartbeat가 아직 유효해서 정상 동작이고, 시간이 지난 뒤에는 202로 받아졌습니다.
- 결론: 객관식 3개와 단답형 2개는 확인됐습니다. 정답이 빈 단답형 SA_03과 주관식 3개는 gemini-3.6-flash가 계속 멈춰서 결과를 못 봤습니다.

### B-7. 난이도·tags·부제목·문제의도를 AI가 채우는지 (실제 AI)
- 명령: 난이도 열을 뺀 엑셀 3문제 `sample3.xlsx`를 `run_real_e2e.py --model gemini-3.6-flash`로 실행
- 출력: `작업 상태: paused | 처리 1/3 | 상태별 {'ai_failed': 2, 'needs_review': 1}`
- 결론: **확인하지 못했습니다.** gemini-3.6-flash가 2건에서 응답하지 않았고 결과 파일도 저장되지 않았습니다. 3.5-flash로 다시 하려던 실행을 중단하셔서 거기서 멈췄습니다.
- 대신 코드 쪽은 확인됐습니다. 등록할 때 `description`을 `{"intent","subtitle","content"}`로 감싸는 동작과 중복 확인(본문만 비교)은 `test_desc_pack.py` 10/10으로 통과했습니다.

### B-8. 1단계 최종 실행
- 명령: `python run_all_tests.py`
- 중간 출력: `프롬프트 점검 ... 실패 결과: 통과 60 / 실패 1`, 이어서 `❌ 길이 예산 20,000자 이내 20,092자`
- 원인: `prompt.md`가 직접 수정되어(난이도·tags는 근거가 부족하면 비움, 조언 구분에서 "난이도·태그" 삭제, 예시 6에 채움 항목 추가) 20,092자가 됐습니다.
- 고친 것: 길이 예산만 20,500자로 올리고 `등록프롬프트.md` 복사본을 맞췄습니다. 프롬프트 내용은 건드리지 않았습니다.
- 최종 출력: `통과 21 · 실패 0 · 건너뜀 1`
